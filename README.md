# PAQA Assignment — Password Validator Tests

Проект демонстрирует параметризованное тестирование на pytest с использованием
кастомных маркеров, регистрацией их в `pytest.ini` и запуском тестов по маркеру.

## Структура проекта

project/
├── validator.py # тестируемая функция
├── pytest.ini # конфигурация pytest, регистрация маркеров
├── tests/
│ └── test_validator.py # параметризованные тесты
├── requirements.txt
└── README.md

## Клонирование проекта

```bash
git clone <https://github.com/snowowman12/my_new_project.git>

```

## Настройка окружения

1. Создать виртуальное окружение:

```bash
python -m venv venv
```

2. Активировать окружение:

- Windows:
```bash
venv\Scripts\activate
```

- macOS / Linux:
```bash
source venv/bin/activate
```

3. Установить зависимости:

```bash
pip install -r requirements.txt
```

Если файла `requirements.txt` ещё нет, создать его с минимальным набором:
pytest
black
flake8
и установить командой выше.

Запустить все тесты:

```bash
pytest
```

Запустить только тесты с маркером `smoke`:

```bash
pytest -m smoke -v
```

## О тестируемой функции

`is_valid_password(password: str) -> bool` — проверяет, что пароль:
- содержит не менее `MIN_PASSWORD_LENGTH` символов;
- содержит хотя бы одну цифру;
- содержит хотя бы одну заглавную букву.

## Кастомные маркеры

| Маркер | Назначение |
|--------|------------|
| `smoke` | быстрые проверки базовой функциональности |

Маркеры зарегистрированы в `pytest.ini`, поэтому pytest не выдаёт
`PytestUnknownMarkWarning` при их использовании.




### Проект автоматизации тестирования на Pytest

Реализация учебного проекта, демонстрирующего работу с различными типами, областями видимости (scope) и фазами жизненного цикла фикстур в фреймворке pytest. 

### 📋 Реализованные требования

1. **Фикстура с scope="module"**: Создается один раз для всего тестового файла. В логах наглядно показано однократное создание через таймстемпы.
2. **Фикстура с autouse=True**: Автоматически применяется к каждому тесту без явной передачи в аргументах.
3. **Вынос в conftest.py**: Общие фикстуры вынесены в специальный файл конфигурации и переиспользуются в двух независимых тестовых модулях.
4. **Yield-фикстура с фазой Teardown**: Реализован гарантированный запуск кода очистки (после ключевого слова yield) по завершении тестов.
5. **Фикстура с scope="session"**: Создан глобальный mock API-клиент, который инициализируется в самом начале тестовой сессии и закрывается в самом конце.

### 🛠 Установка и запуск

### 1. Подготовка окружения

Убедитесь, что у вас установлен Python версии 3.8 или выше. Разверните виртуальное окружение и установите pytest: 

bash

# Создание виртуального окружения
python -m venv .venv

# Активация окружения (Windows)
.venv\Scripts\activate

# Активация окружения (macOS/Linux)
source .venv/bin/activate

# Установка зависимостей
pip install pytest

Используйте код с осторожностью.

### 2. Структура проекта

Убедитесь, что файлы расположены в следующей иерархии: 

text

my_new_project/
│
├── conftest.py          # Глобальные фикстуры (session, autouse)
├── pytest.ini           # Конфигурация запуска pytest
├── test_module_one.py   # Модуль с тестами БД (scope="module")
└── test_module_two.py   # Модуль с тестами API (переиспользование)

Используйте код с осторожностью.

### 3. Запуск тестов

Чтобы увидеть логи фикстур, подробные таймстемпы и результаты фазы teardown, запустите тесты через модуль Python: 

python -m pytest

Используйте код с осторожностью.

*(Параметры вывода -s -v уже автоматически прописаны в настройках pytest.ini)*.
